📐 1. Metodologia

Sonora Digital Corp opera bajo una jerarquia de desarrollo en 7 capas que va desde el valor puro hasta la implementacion tecnica. Ningun codigo se escribe sin pasar por las capas superiores primero.

JERARQUIA DE DESARROLLO (OMEGA PROMPT v10.0) ┌─────────────────────────────────────────────────────┐ │ VDD Value Driven Development ¿CREA VALOR? │ ├─────────────────────────────────────────────────────┤ │ EDD Evidence Driven Development ¿HAY DATOS? │ ├─────────────────────────────────────────────────────┤ │ PDD Policy Driven Development ¿CUMPLE REGLAS?│ ├─────────────────────────────────────────────────────┤ │ ODD Operational Driven Development ¿ES OPERABLE? │ ├─────────────────────────────────────────────────────┤ │ SDD Specification Driven Dev. ¿TIENE SPEC? │ ├─────────────────────────────────────────────────────┤ │ BDD Behavior Driven Development ¿GHERKIN? │ ├─────────────────────────────────────────────────────┤ │ TDD Test Driven Development ¿PASAN TESTS? │ └─────────────────────────────────────────────────────┘ │ ▼ IMPLEMENTACION │ ▼ TECNOLOGIA │ ▼ HERRAMIENTAS
Regla de oro: Tools never drive decisions. Value drives decisions.
Nunca optimizar por: Actividad, Novedad, Adopcion de tools, Frameworks, Modelos.
Siempre optimizar por: Valor, Revenue, Confiabilidad, Simplicidad, Reusabilidad, Supervivencia, Automatizacion.

✅ 6. Aciertos (Lo que funciona bien)

1. Jerarquia VDD→TDD — Ningun codigo se escribe sin pasar por 7 capas de validacion. Previene building-at-the-wrong-level. Score maximo alcanzado: 84/100.
2. Pipeline SDD con agentes especializados — 6 agentes con modelos distintos (deepseek para spec, llama para codigo, qwen para diseño). Cada agente optimo para su fase.
3. Constitucion v10.0 — 6 documentos que definen absolutamente todo: identidad (SOUL), reglas (10-RULES), paths (TRUTH), operacion (OMEGA-PROMPT), contrato (CONTRATO), integridad (CHECKSUMS).
4. 10 Sub-OS Architecture — Sales, Dev, Support, Agent, Knowledge, Finance, Security, Ops, Quality, Strategy. Cada uno con prompt, agent, habilidades y metricas propias.
5. Enterprise Score ≥ 60 — Sistema de scoring que obliga a medir cada iniciativa contra 10 dimensiones. Previene feature creep y work-for-work.
6. Git hooks + CI gates — pre-commit bloquea sin spec activa. post-commit actualiza CATALOG y emite eventos. CI enforce tests + lint + score.
7. Event-driven nervous system — Todo negocio emite eventos (lead_received, contract_signed, payment_received, workflow_failed). Nada depende de memoria humana.
8. Capability-first, not project-first — No se construyen proyectos aislados. Se construyen capacidades reusables (Lead Gen, Sales Ops, Content Production, Software Delivery).
9. Founder Elimination Framework — Identificar y automatizar toda dependencia del fundador: manual work, decisions, follow-up, coordination, memory.
10. Product Factory Principle — Toda solucion exitosa se convierte en: Template → Framework → Capability → Product → Marketplace Asset.

❌ 7. Errores (Lo que aprendimos)

1. HTTPS certs caidos — Los certificados SSL de sonoradigitalcorp.com y api.sonoradigitalcorp.com expiraron. Nginx apunta a /etc/letsencrypt/live/ que no existe. Todo el trafico HTTPS muerto.
Por que paso: Sin renovacion automatica (certbot renew cron no configurado).
Fix: certbot certonly --nginx -d sonoradigitalcorp.com -d www.sonoradigitalcorp.com -d api.sonoradigitalcorp.com && systemctl reload nginx
2. Hermes Gateway caido permanentemente — hermes-gateway.service no existe (unit not found). El MCP endpoint :8000 lleva muerto ~7 dias.
Por que paso: El unit file se elimino o nunca se reinstalo tras un deploy. Nadie lo monitoreo.
Fix: Reinstalar unit systemd o migrar el servicio a Docker compose.
3. Telegram Bot Token muerto — ABE_FENIX_BOT token no funciona. Abe-daemon reporta cada 10 minutos. @ABEfenix_bot no responde.
Por que paso: Token probablemente revocado por inactividad o recreacion del bot en BotFather.
Fix: Ir a @BotFather → regenerar token → actualizar .env
4. OpenClaw no puede usar deepseek-r1:7b — Error: "Unknown model" aunque el modelo existe en Ollama. OpenClaw exige OLLAMA_API_KEY incluso para modelos locales.
Por que paso: Bug de OpenClaw — requiere auth key aunque el provider sea local. El mejor modelo (7B reasoning) no disponible para el gateway.
Fix: export OLLAMA_API_KEY=dummy en ~/.openclaw/gateway.env
5. Swap al 65% — 1.3GB/2GB usados. Con 12 containers + 6 modelos Ollama + Python processes, la RAM es el cuello de botella.
Por que paso: 11.6GB RAM total con multiples servicios compitiendo. Sin limits en containers.
Fix: Agregar swap (4GB), reducir modelos no usados, limitar RAM de containers.
6. Sin disaster recovery plan — Single VPS sin replica, sin backup caliente, sin failover. Si OVH cae, todo cae.
Leccion: Se automatizo backup diario pero no restauracion ni failover.
7. Browser scraping fragil — Instagram bloqueado (login wall), Wikipedia bloquea datacenter IPs (403). Los scrapers de estas fuentes fallan constantemente.
Leccion: Sin API keys oficiales, el scraping es inherentemente fragil. Necesario fallback por weight > health-first.
8. ACERTIEMPOS.md vacio — El archivo de lecciones y errores esta creado pero nunca se poblo. Las lecciones se pierden entre sesiones.
Leccion: El ENGRAm captura sesiones, pero no hay un catalogo centralizado de errores.

🔬 13. Logica de Ingenieria de Procesos

Principios Fundamentales

1. Event-Driven Everything — Toda actividad de negocio empieza con un evento. No hay workflow que dependa de memoria humana. Ejemplos: lead_received, contract_signed, workflow_failed.
2. Capability-First, Not Project-First — No se construyen proyectos. Se construyen capacidades reusables. Cada implementacion debe incrementar el catalogo de capacidades.
3. Product Factory — Toda solucion exitosa sigue la cadena: Template → Framework → Capability → Product → Marketplace Asset.
4. Founder Elimination — Identificar y convertir toda dependencia del fundador en: Evento, Politica, Workflow, Skill, Capability, o Responsabilidad de agente.
5. Evidence Over Intuition — Toda decision requiere evidencia (EDD layer). No se construye por "sentir" que es buena idea.
6. Anti-Fragility by Design — El sistema debe sobrevivir: cambios tecnologicos, caidas de vendors, outages de infraestructura, incidentes de seguridad, ausencia del fundador.
7. Measurement Before Action — Toda iniciativa arranca con un Score baseline. Toda iniciativa termina con un Score comparativo. Si no se puede medir, no se construye.

Cadena de Validacion

ESPEC → SCORE → GHERKIN → TESTS → CODE → EVENTS → ADR → LECCION Cada spec debe pasar por: 1. Aprobacion humana (PR con 1 approval) 2. Score ≥ 60 (10 metricas) 3. Gherkin scenarios escritos 4. Tests pasando (CI verde) 5. Events emitidos 6. ADR registrado 7. Leccion documentada 8. Score post-mortem

Ciclo de Vida de una Iniciativa

1. IDEA → Strategy OS evalúa 2. SPEC → sdd-spec (deepseek) genera 3. SCORE → Se calcula baseline 4. GATE → Score ≥ 60? Si no, kill 5. DESIGN → sdd-design (qwen3) planifica 6. APPLY → sdd-apply (llama3) codifica 7. VERIFY → sdd-verify (llama3) tests + quality 8. ARCHIVE → sdd-archive documenta 9. EVENTS → Todo queda registrado 10. SCORE → Post-mortem, comparar delta

📓 15. Lecciones Aprendidas (de las specs)

SPEC-20260701-004: Capability-first abstractions: registry fuerza todas las abstracciones. SDK executor bridge necesario para conectar engine con collectors multi-step. Fallback por weight > health-first (mas robusto).
SPEC-20260701-005: Browser scraping es fragil pero necesario sin API keys. Instagram bloqueado (login wall). Wikipedia bloquea datacenter IPs (403). Sync cron no instalado — script disponible en scripts/install-sync-cron.sh.
PROTOCOLO: 7 mandamientos. Los errores mas repetidos: construir sin verificar output, probar solo localhost, hacer varias cosas en paralelo, ignorar CI rojo, documentar al final, asumir que uno recuerda.
ESPEC-20260701-007: El auto-healing loop funciona pero depende de que el abe-daemon este vivo. Si el daemon muere, no hay watchdog. Se necesita un watchdog externo (cron-based o HW).
ESPEC-20260701-010: Hermes Bridge necesita reinicio periodico. El MCP gateway en Node.js es estable pero el bridge Python muere por memory leaks. Suggested fix: Restart=always con RestartSec=30.
ESPEC-20260701-012: La migracion V2 de agents necesita compatibilidad hacia atras. Los tests legacy no se actualizaron automaticamente. Score 66 — el mas bajo. Leccion: no mezclar migracion con features nuevas.
