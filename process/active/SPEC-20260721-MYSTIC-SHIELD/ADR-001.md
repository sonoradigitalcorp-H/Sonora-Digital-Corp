# ADR-20260721-001 — Arquitectura: MCP Server + FastAPI + Landing Estática

| Campo | Valor |
|-------|-------|
| **ID** | `ADR-20260721-001` |
| **Fecha** | 2026-07-21 |
| **Spec** | `SPEC-20260721-MYSTIC-SHIELD` |
| **Estado** | aceptado |

---

## Context

Mystic Shield necesita tres capas:
1. **Core engine**: escanea, analiza con IA, genera PDF/audio, envía WhatsApp/Email
2. **API**: expone endpoints REST para el frontend y clientes externos
3. **Landing**: página pública para capturar leads

Opciones de arquitectura: monolitico (todo en una app) vs separado (MCP + API + static).

---

## Decision

**Arquitectura separada en 3 procesos:**

```
Frontend (estático) → FastAPI (API) → MCP Server (core engine)
```

1. **MCP Server** (`shield_mcp.py`, puerto 8930): Core engine como servidor MCP. Corre como proceso independiente. Expone tools `shield_diagnose` y `shield_send_report`. Puede ser llamado por OpenClaw, Hermes, o cualquier agente MCP.

2. **FastAPI** (`main.py`, puerto 8931): Backend REST. Sirve la landing estática (montada como StaticFiles), expone endpoints `/api/*`. Se comunica con el MCP Server por import directo (mismo proceso en MVP, separado en producción).

3. **Landing estática** (`index.html`): HTML+CSS+JS puro. Sin framework. Servida por FastAPI. Formulario POST a `/api/request-diagnosis`.

**Razones:**
- MCP server es reutilizable por otros agentes (OpenClaw, Hermes, OpenCode)
- Separación de concerns: cada capa puede escalar independientemente
- Landing estática = cero mantenimiento, deploy instantáneo
- FastAPI es familiar (ya tenemos experiencia con él en el repo)

---

## Options Considered

| Opción | Pros | Contras |
|--------|------|---------|
| **A. 3 capas separadas** (elegida) | Reutilizable, escalable, clara | 2 procesos que administrar |
| **B. Todo en FastAPI** | Un solo proceso, simpler | Core no reutilizable por otros agentes |
| **C. Todo en OpenClaw skill** | Zero infra nueva | OpenClaw no es un API server público |
| **D. Next.js full stack** | Mejor DX frontend | Más peso, más deuda técnica |

---

## Consequences

- MCP server puede ser llamado desde OpenCode CLI (`shield_diagnose`)
- FastAPI puede reemplazarse por n8n webhook en futuro
- Landing puede migrarse a Next.js cuando haya portal cliente
- 2 puertos ocupados (8930, 8931)

---

## Lessons

- MCP sobre HTTP es más sencillo que MCP sobre STDIN para integración REST
- StaticFiles de FastAPI sirve HTML perfectamente para MVP
- wacli como subprocess es frágil — considerar python-whatsapp-api en futuro
