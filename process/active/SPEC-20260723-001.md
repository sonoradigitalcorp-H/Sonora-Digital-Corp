## 1. Objetivo

Crear una página pública interactiva 3D que presente agentes de IA como un sistema de galaxias con cuerpos celestes orbitales, demostrando capacidades de Aztro Tech para clientes potenciales y permitiendo onboarding inmediato vía teléfono móvil.

---

## 2. Value Driver

- **Revenue**: Demo pública que convierte visitantes en leads calificados para Aztro Tech
- **Scalability**: Arquitectura multi-tenant que reutiliza infraestructura SDC existente
- **Automation Impact**: Onboarding sin intervención humana — el usuario se conecta y recibe su agente
- **Customer Value**: Experiencia visual única que educa al cliente sobre capacidades disponibles
- **Founder Independence**: Demo auto-servicio que elimina dependencia del fundador para presentaciones
- **Knowledge**: Patrón reutilizable de visualización 3D + onboarding para futuros productos

---

## 3. Functional Requirements

| FR# | Descripción |
|-----|-------------|
| FR1 | La página principal renderiza una galaxia 3D con 9 cuerpos celestes (Mercurio, Venus, Tauro, Marte, Júpiter, Saturno, Urano, Neptuno, Plutón) usando Three.js |
| FR2 | Cada cuerpo celeste orbita con animación fluida (60fps) y responde a interacción del usuario (hover, click) |
| FR3 | Al hacer zoom en un cuerpo celeste, aparecen tarjetas flotantes estilo Yu-Gi-Oh que muestran capacidades, beneficios y especificaciones del agente |
| FR4 | Las tarjetas tienen animación de texto flotante que aparece/desaparece con efecto de fade-in/fade-out |
| FR5 | El usuario puede iniciar onboarding escaneando un QR o haciendo clic en un enlace que conecta su teléfono |
| FR6 | El sistema genera un agente personalizado asignando capacidades según las necesidades del usuario (multi-tenant) |
| FR7 | El pipeline de voz STT/TTS se configura automáticamente vía WhatsApp (wacli), con capacidad de extracción a cualquier red social |
| FR8 | El agente provisionado integra OpenClaw (operación), Hermes (gateway MCP), OpenCode (skills/tools) según el plan del usuario |

---

## 4. Success Criteria

- [ ] La galaxia 3D se renderiza en navegadores modernos (Chrome, Firefox, Safari) a ≥30fps
- [ ] Un usuario nuevo completa el onboarding (escanear QR → recibir agente) en <3 minutos
- [ ] Las capacidades asignadas difieren correctamente entre tenants multi-tenant
- [ ] El pipeline de voz STT/TTS funciona end-to-end vía WhatsApp
- [ ] El score del SPEC es ≥60/100
- [ ] Todos los tests Gherkin pasan (happy path + edge cases)
- [ ] Los eventos se emiten correctamente a `state/events/events.jsonl`

## 6. Edge Cases

- [EC1] Navegador sin soporte WebGL (fallback a vista 2D estática con mensaje informativo)
- [EC2] Conexión de red lenta o inestable durante carga de assets 3D (progressive loading + skeleton screen)
- [EC3] QR escaneado desde dispositivo sin WhatsApp (ofrecer alternativa Telegram o enlace web)
- [EC4] wacli no disponible o API de WhatsApp no configurada (degradar gracefully a modo texto)
- [EC5] Dos tenants concurrentes con configuraciones contradictorias (aislamiento garantizado por tenant_id)
- [EC6] Modelo LLM no disponible para STT/TTS (fallback a STT local si disponible, o modo solo texto)
- [EC7] Usuario cierra el navegador mid-onboarding (recuperar sesión via enlace único)
- [EC8] Mobile device con memoria limitada (reducir resolución de texturas 3D automáticamente)

## 7. Technical Approach

### Frontend (3D Galaxy)

```
apps/agent-galaxy/frontend/
├── src/
│   ├── components/
│   │   ├── GalaxyScene.tsx        # Three.js scene principal
│   │   ├── CelestialBody.tsx      # Componente de cuerpo celeste
│   │   ├── AgentCard.tsx          # Tarjeta estilo Yu-Gi-Oh
│   │   ├── FloatingText.tsx       # Texto animado flotante
│   │   ├── OnboardingModal.tsx    # Modal de onboarding
│   │   └── QRCode.tsx             # Generador de QR
│   ├── services/
│   │   ├── galaxy-data.ts         # Datos de los 9 agentes
│   │   └── api-client.ts          # Cliente FastAPI
│   ├── hooks/
│   │   ├── useGalaxy.ts           # Hook para estado de la galaxia
│   │   └── useOnboarding.ts       # Hook para flujo de onboarding
│   └── App.tsx
├── public/
│   ├── textures/                  # Texturas planetarias
│   └── models/                    # Modelos 3D optimizados
└── package.json
```

**Stack**: Three.js + React Three Fiber + drei (helpers)
**Fallback**: Canvas 2D para navegadores sin WebGL

### Backend (Multi-tenant API)

```
apps/agent-galaxy/backend/
├── main.py                        # FastAPI entry point
├── api/
│   ├── galaxy.py                  # GET /api/galaxy — datos de la galaxia
│   ├── onboarding.py              # POST /api/onboard — iniciar onboarding
│   ├── tenant.py                  # POST /api/tenants — crear tenant
│   ├── voice.py                   # POST /api/voice/config — configurar STT/TTS
│   └── health.py                  # GET /health
├── services/
│   ├── galaxy_service.py          # Lógica de datos de la galaxia
│   ├── tenant_service.py          # Provisionamiento multi-tenant
│   ├── capability_service.py      # Asignación de capacidades
│   └── voice_service.py           # Pipeline STT/TTS vía wacli
├── models/
│   ├── tenant.py                  # Pydantic models
│   ├── capability.py
│   └── agent_config.py
└── db/
    ├── tenant_store.py            # SQLite (prototype) / Postgres (production)
    └── event_store.py             # JSONL events
```

**Stack**: FastAPI + SQLite (prototype) + JSONL events
**Multi-tenant**: tenant_id como clave de aislamiento, datos separados por tenant

### Voice Pipeline

```
Usuario → WhatsApp (wacli) → STT (OpenAI Whisper / local) → Proceso → TTS (ElevenLabs / local) → WhatsApp
                                      ↑
                                  Cualquier red social (configurable)
```

### Integration

- **OpenClaw**: Operación del agente asignado — el agente provisionado usa OpenClaw como motor operativo
- **Hermes**: Gateway MCP que conecta el agente a herramientas (skills, tools, servers)
- **OpenCode**: Skills y tools del repositorio SDC disponibles según capacidades asignadas
- **Engram**: Memoria del tenant persistida en la capa de memoria correspondiente

## 10. Kill Criteria

- Three.js no logra renderizar a ≥30fps en Chrome/Firefox/Safari después de 2 sprints de optimización
- wacli no es viable para producción y no existe alternativa de WhatsApp API en 30 días
- El onboarding toma >10 minutos para un usuario técnico (indica complejidad excesiva)
- Costo por tenant provisionado >$5 USD/mes sin revenue correspondiente
- No hay interés de clientes potenciales después de 3 demostraciones públicas

---

## 11. Scale Criteria

- ≥50 tenants activos con <5% error rate en onboarding → migrar a PostgreSQL + Redis
- ≥10 demostraciones por semana con ≥30% conversión → producción readiness
- Pipeline de voz estable por 30 días consecutivos → escalar a multi-red social
- OpenClaw + Hermes integrados sin incidentes por 14 días → añadir más agentes/planetas
- Enterprise score ≥60 → iniciativa aprobada para expansión

## Disclaimer: PREVIEW/PROTOTYPE Mode

Este SPEC define un prototipo funcional para demostración y validación de concepto.
**NO es una especificación de producción.**

Decisiones de producción (escala, alta disponibilidad, backups, CI/CD, SSL)
se abordarán en un SPEC separado si este prototipo valida las scale criteria.

Infraestructura prototype:
- Frontend: Vite dev server (localhost)
- Backend: FastAPI + SQLite
- Events: JSONL flat file
- Voice: wacli + OpenAI Whisper API

Infraestructura production (future):
- Frontend: Static hosting (CloudFront / Vercel)
- Backend: Docker + Postgres + Redis
- Events: Postgres + event streaming
- Voice: WhatsApp Business API + local STT/TTS
